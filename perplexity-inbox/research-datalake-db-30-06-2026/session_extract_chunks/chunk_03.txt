### What the optimal environment looks like

**Deterministic pre-processing handles:**
- Temporal filtering (`valid_from`/`valid_until` — the only metadata type with consistent +F1). A date comparison is deterministic. Don't ask the model to infer it from prose.
- Source/domain filtering (Multi-Meta-RAG: $in/$nin operators on metadata). That's a database query, not a language task.
- Graph traversal for multi-hop (IIER's CIG). Walking edges is deterministic. The model only synthesises at the end.
- Chunk deduplication, field capping, format normalisation — all code.

**AI handles:**
- Semantic understanding, synthesis, reasoning across retrieved evidence.
- Query decomposition templates (SearchNuggets — but only materialisation, not the traversal itself).

**What to strip out:**
- Confidence scores — models cite them but accuracy *drops* when they do.
- Provenance chains — 0–6% utilisation rate. The model literally ignores them.
- JSON wrapping — costs tokens, destroys narrative continuity, adds no value over Markdown.
- Adjacent chunk expansion — hurts precision (Dadopoulos negative finding).

### Your math point

Directly supported. Zerhoudi found that when you ask a model to do probabilistic reasoning over confidence scores it *can* execute the operation (94% correctness on mechanics) but still produces worse answers — because it's now competing with temporal reasoning for attention, and picks the easier operation. 

The implication: route deterministic operations (date comparison, arithmetic, graph traversal, schema validation) to code *before* the model sees the context. The model gets a clean, pre-resolved fact, not a problem dressed up as a fact.

**The right question to AI is a synthesis question. The wrong question is a computation question with a probabilistic wrapper on it.**

The research validates the architecture you're already building: deterministic pipeline → clean, minimal, task-matched context → AI synthesises. That's the whole result.

You're not conflating anything. You've got it exactly right, just in plain language.

The technical term is **signal-to-noise ratio in the context window**. Every token the model receives costs attention. Attention is finite. If you fill the window with tokens that aren't load-bearing for the answer — JSON wrappers, provenance URLs nobody uses, adjacent chunks that aren't relevant — you are literally crowding out the tokens that matter.

The Zerhoudi result is the proof: adding confidence score fields (tokens) caused the model to *correctly read* those tokens but *wrongly answer* the question — because those tokens competed for attention with the temporal window tokens that actually contained the answer.

So your instinct is:

**Fewer, better tokens > more tokens.**

The deterministic pipeline's job is to be a ruthless editor. It decides what tokens the AI even sees. Graph traversal, date filtering, source scoping — all of that is token curation. By the time the model reads the context, every token in there should be earning its place.

You're not missing terminology. You've arrived at the principle the research took 24,000 evaluated responses to confirm.

The probability isn't in the hop. The probability is in the **confidence of the output** given that the hop was correctly constructed. Those are completely different things.

So the Python/Rust layer isn't just a gate at the end — it's doing the deconstruction at the front too. It takes the business question and breaks it into its logical constituents before AI ever sees it. AI receives:

- This is the question type
- These are the relevant variables
- This is the methodology lens
- Here are the specific data points

Then the hop is logical, not probabilistic. The model isn't guessing which path — it's walking a pre-lit path and doing what it's actually good at: reasoning over the assembled constituents and synthesising a coherent answer.

1. Quality of the constituent assembly (your deterministic layer's job)
2. Confidence interval on the output (your Taguchi gate's job)
