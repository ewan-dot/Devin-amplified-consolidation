# Task: Deterministic Prompt and Rules Sync Pipeline

**Goal:** Build a deterministic synchronization script (`harness/sync_ledger_to_dbs.py`) that updates the indexing databases (`amplified_brain` and `cove`) from the master file ledger, preventing semantic drift between departments.

---

## 1. Context & Architecture

We have established the **Assertion-Context Boundary**:
1. **The Filesystem Ledger (Master):** The single source of truth. System prompts and rules are stored as Markdown files with our 19-field Dual-YAML headers (e.g., `/brain/logic_packets/` and `/prompts/`).
2. **The Read Index (`amplified_brain`):** Stores coordinates, entities, and logical relationships (AGE graph).
3. **The Department Orchestrator (`cove`):** Stores deterministic execution variables (e.g., `system_prompts` table).

To prevent drift, the dissemination of updates from the file ledger to the databases must be **completely deterministic (code-driven)**, not generated by an LLM.

---

## 2. Technical Requirements

Write a Python script `harness/sync_ledger_to_dbs.py` that implements the following pipeline:

### Step 1: Parse and Validate
*   Scan `/prompts/` and `/brain/logic_packets/`.
*   Parse the Dual-YAML header of each changed file.
*   Assert all 19 required metadata fields (e.g., `title`, `document_type`, `version`, `file_hash_sha256`).
*   Compute the SHA-256 hash of the content to verify it matches `chunk_hash_sha256`. Reject the sync if hashes mismatch.

### Step 2: Sync to Department DB (`cove`)
*   For any prompt file (e.g., `/prompts/coder.md`), parse the version and text.
*   Connect to the `cove` database (using `db_harness` check).
*   Upsert the prompt directly to the `system_prompts` table:
    ```sql
    INSERT INTO public.system_prompts (id, agent_role, layer, prompt_text, is_active, version, updated_at)
    VALUES (%s, %s, %s, %s, %s, %s, NOW())
    ON CONFLICT (id) DO UPDATE 
    SET prompt_text = EXCLUDED.prompt_text, version = EXCLUDED.version, is_active = EXCLUDED.is_active, updated_at = NOW();
    ```

### Step 3: Sync to Main DB Graph (`amplified_brain`)
*   For logic packets, update the corresponding node properties and coordinates in the Apache AGE `business_brain` graph.
*   Store the new `file_hash_sha256` in the graph node.

### Step 4: Verification Checks
*   Provide a `--verify` flag that connects to both databases, pulls the current active prompt/node hashes, and asserts that they match the filesystem hashes.
*   Exit with code `0` on match, or code `1` with a detailed drift report on mismatch.

---

## 3. Verification Plan

*   **Test Integration:** Run the script locally on the Mac Mini, modify the prompt `/prompts/coder.md`, and verify that the `system_prompts` table in `cove` immediately reflects the new version and text.
*   **Stale-State Test:** Artificially modify a row in `cove.system_prompts` and run `python sync_ledger_to_dbs.py --verify`. Assert that it detects the drift and triggers a self-healing resync.
