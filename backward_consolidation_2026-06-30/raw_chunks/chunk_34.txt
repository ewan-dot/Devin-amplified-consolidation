---

### 1. Certainty (`<certainty>`)
*   **Grammatical Rule:** Triggered by **imperative verbs** (e.g., *use*, *do*, *be*), **deontic modal operators** of obligation (e.g., *must*, *required*, *shall*), and **indicative assertions** containing absolute quantifiers (e.g., *never*, *always*, *strictly*).
*   **Context Rule:** The nouns referenced must resolve directly to canonical targets in [ESTATE-TAXONOMY.md](file:///Users/ewansair/ingestion-to-research-pipe/perplexity-inbox/ESTATE-TAXONOMY.md) with zero overlap. 
*   *Example:* `"<certainty>Run the gatekeeper checks.</certainty>"` is certain because it uses an imperative verb and points to a unique, mapped script.

---

### 2. Ambiguity (`<ambiguity>`)
*   **Grammatical Rule:** Triggered by **epistemic modals** of possibility (e.g., *might*, *should*, *could*), **existential quantifiers** without bound variables (e.g., *someone*, *somewhere*, *something*), and **comparative adjectives** without a specified baseline (e.g., *better*, *faster*, *cleaner*).
*   **Context Rule:** High semantic entropy where a term maps to multiple possible targets in the estate.
*   *Example:* `"<ambiguity>Test the database.</ambiguity>"` is ambiguous because the grammar specifies "the database" but the context contains six distinct databases (`cove`, `amplified_brain`, `vellum`, etc.).

---

### 3. Metaphor (`<metaphor>`)
*   **Grammatical Rule:** Identified by **semantic domain mapping transfer** (cross-domain projection), where vocabulary from a physical or organic source domain is mapped onto an abstract target domain.
*   **Context Rule:** Non-literal expressions used to establish structural mental models.
*   *Example:* `"<metaphor>Stab the post-it notes on the spike.</metaphor>"` is a metaphor because it uses physical insertion vocabulary to describe a database projection query.

---

### 4. Imprecision (`<imprecision>`)
*   **Grammatical Rule:** Flagged when the speaker uses a **colloquial shorthand** or a generic noun phrase to describe a highly specific technical component.
*   **Context Rule:** Misalignment with the canonical names registered in the System of Record.
*   *Example:* `"<imprecision>cove-postgres</imprecision>"` is imprecise because it refers colloquially to the Docker container, whereas the instruction context requires targeting a specific database inside that container (e.g., `amplified_brain`).

---

### ASSISTANT (Session 6ff55ae9)
This is the definitive failure mode of rigid, rule-bound systems. 

**"My words are messy. Your words are precise. Your mistakes are precisely wrong. Mine are imprecisely wrong."**

When you make an imprecise mistake (like writing "Seth Golden" or "cve databse"), your human brain knows directionally what you mean. But when the AI receives that, its rigid search engine checks for the exact string, fails to find it, concludes it doesn't exist, and creates a brand-new duplicate entry right next to the original. That is **precise wrongness**—it executes a perfectly logical sequence to produce a stupid result.

To solve this, we must build a **fuzzy tolerance buffer** into the truffle dog's snout (our intake tools) so it behaves less like a computer compiler and more like a tracker:

---

### 1. The Fuzzy matching Gate: Levenshtein Distance
We will update our intake scripts to ensure they never perform strict binary checks on names. Instead, they must run a string similarity calculation (like Levenshtein distance, which counts the number of single-character edits between two words):

$$\text{Similarity}(A, B) = 1 - \frac{\text{Distance}(A, B)}{\max(\text{len}(A), \text{len}(B))}$$

*   **How it works:** If you type "Seth Golden," the system calculates the distance to "Seth Godin." Since the similarity is high ($> 80\%$), the system blocks the creation of a new entry and automatically aligns it to the existing target.
*   **The Rule:** The AI is prohibited from declaring a resource "missing" or creating a new node until it has scanned the immediate neighborhood of existing names for close matches.

---

### 2. Semantic Neighborhood Mapping (The Voronoi Cell)
In our Python pipelines, when a term or coordinate is computed, it drops into a neighborhood cell. 
*   If a misspelling lands right on the boundary between cells (experiencing high ambiguity), the system is programmed to flag **Linguistic Friction**.
*   Instead of making a precise guess and getting it wrong, the system must halt and present the close options: *"I found 'Seth Godin' right next to your input. Am aligning to that."*

---

### 3. The Contract on Spelling and Redundancy
*   **Our Job:** We must run fuzzy lookups on all inputs. We cannot treat a misspelling as a license to create duplicate code or files. We must check the "surrounding desk" first.
*   **Your Job:** You can continue to write messily. The system's job is to absorb the imprecision and map it to the precise technical target without complaining or creating junk.

This is the only way a precise machine can safely collaborate with a creative, fast-moving human without polluting the database with duplicate assets.

Exactly. At every single level of the architecture, we have engineered an **autocorrecting safety net (an "Arsewiper")** to catch the friction and messiness before it corrupts the database. 

Instead of assuming the human or the AI will be perfect, we assume they will make mistakes, and we deploy a safety net at each gate.

Here are the four active levels of safety nets we have built into the codebase:

---

### Level 1: The Input Autocorrect (`term_gate.py` & `ewans_mouth.py`)
*   **The Job:** Absorbs your messy, colloquial, or misspelled words.
*   **The Safety Net:** It runs your raw text through the canonical taxonomy. If you type a technical shorthand, it acts like text autocorrect, mapping it back to the exact database or server target without you needing to remember the exact technical name.

### Level 2: The Semantic Autocorrect (The Voronoi Cell)
*   **The Job:** Maps research chunks to logical coordinates.
*   **The Safety Net:** Instead of requiring a chunk to match a category label perfectly, the pipeline places it in a coordinate space. The chunk automatically "snaps" to the nearest established reasoning primitive (the nearest neighbor in the Voronoi cell). It prevents the system from creating redundant categories just because the phrasing was slightly different.

### Level 3: The Format Guard (`glasses_loader.py` & `shape_gate.py`)
*   **The Job:** Audits metadata files before they are saved to the database.
*   **The Safety Net:** If an agent tries to write a file with too many fields ($>20$), or misses a required key, the loader catches it on read/write. It reports the exact error and blocks ingestion, preventing messy files from cluttering the data lake.

### Level 4: The Environment Gatekeeper (`gatekeeper.py`)
*   **The Job:** Protects the production server and database states from execution errors.
*   **The Safety Net:** Before running any pipeline mutations, it checks the environment (making sure we are not on `main`, verifying that database ports are open, and asserting that pgvector dimensions are strictly `384`). If anything is misconfigured, it fails loud and halts the run.

---

### The Design Philosophy
By building these checks at every step, we ensure the system is **resilient to fuzziness**. You can write messy, fast-moving thoughts; the agents can write code in parallel worktrees; and the "arsewipers" silently clean up the alignment, compile the rules, and log the state to Vellum in the background. It is text autocorrect, but for business intelligence operations.
